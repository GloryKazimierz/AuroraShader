# 水面 M2：反射颜色过滤与已知遮挡回退

状态：在独立 D 盘目录完成，并通过原生 OpenGL 验证。这是局部反射画质改进，不代表完整水体已完成，也不是 Minecraft 实机验收。

## 行为与适用范围

已有的 `WATER_OPTICS=1` 可选路径现在区分“确实有物体挡住”和“屏幕信息不足”。默认依旧关闭；原有风格、渲染模式、调试与硬件能力条件保持。没有新增设置、缓冲、渲染阶段或历史帧，也不依赖硬件光追。关闭光学传输时仍使用原 W3 路径。反射强度为零、原生透明度以及相机雾的行为保持。

命中后，只在邻近数据属于连续局部平面时过滤一个像素范围的反射颜色。这样可以平滑移动的明暗边缘，并拒绝跨深度跳变、折角或无效数据的颜色混合。它尚未解决微小波纹引起的高光闪烁、时域抗锯齿或粗糙度反射瓣。

| 已有证据 | 处理 |
| --- | --- |
| 屋顶有不透明深度，但没有有效 W1 颜色 | 已知遮挡：不能从屋顶后面补入解析天空。 |
| 已命中几何，但方向光份额无效，或颜色置信度为零 | 仍是已知遮挡；未使用的反射能量退回透射，不露出天空。 |
| 数据格式、数值或尺寸异常 | 保守拒绝天空替换。 |
| 经过天空深度像素后仍可命中有效墙面 | 继续搜索墙面。 |
| 射线离屏、用尽步数或距离，或只见清空深度 | 信息未解决，不等于证明天空畅通；保留原有局部天空光近似回退。 |

最后一项仍是限制：当前屏幕快照无法补出屏幕外或未记录的遮挡层。局部天空光也不是完整可见性判断。SSR 是屏幕空间射线搜索，不是硬件光追或路径追踪。

## 接口和读取上限

活动光学路径新增 `traceWaterSceneClassified(...)`，结果为 `UNRESOLVED=0`、`HIT=1`、`OCCLUDED=2`、`INVALID=3`；原 `traceWaterScene` 接口保留。原有搜索、命中位置、深度与置信度约定没有改变。

`waterFilteredReflectionRadiance(hitPixel, hitView, nearestRadiance)` 缓存中心、四个轴向邻居，以及最多一个对角邻居。每份记录验证颜色/有效性、配对深度、不透明深度及方向光份额。上限为 **六份不同记录、24 次显式纹理读取**。四组单侧切线法线需要一致（点积至少 0.99）；贡献点还须满足局部平面距离阈值 `clamp(0.0005 * 观察深度, 0.025, 0.15)` 方块。支持数据不足时退回原命中颜色，不引入历史反馈、大数组或 mip 链。

过滤使用雾前场景颜色，再施加水面到反射物体这一段的空气雾；表面到相机的雾仍只施加一次。

## 验证证据

[原生报告](validation/WATER_M2_reflections.json) 保存全部暂存 shader 的 SHA256 和 Intel Iris Xe / OpenGL 3.3 驱动信息。测试包括八种场景各 64 个移动相位、八种射线状态，以及真实 composite shader 的解析屋顶/开放对照。

- 水平、垂直、斜平面亮边：相对独立像素积分真值，最近采样 RMS 为 2.03225，过滤后为 0.00000712–0.00001034；最大相邻帧变化从 8 降为 0.705185。
- 角点覆盖：最近采样丢失全部亚像素细节，RMS 为 1.32066；过滤后为 0.00000525。这里证明恢复细节，并非声称变化幅度比恒定零值更小。
- 深度台阶、折角、无效邻居及恒定颜色控制均精确符合预期。
- 屋顶已知遮挡 1,399 个归属水面的像素、方向光份额污染 154 个像素，相对纯透射的天空泄漏误差均为零；1,326 个对应开放/未解决像素仍保留可区分的天空回退。

在本机运行完整专项验证并生成一张新对照图：

```powershell
python -B tools/validate_gpu.py --suite water-stability --debug-plate docs/validation/NEW_ROOF.png
```

证据来自合成场景和真实显卡驱动。Iris 游戏运行、其他显卡、资源包和完整帧性能尚未观测。未命中射线的搜索成本由另一个性能阶段处理，此处不宣称游戏帧率提升。

## 后续：波纹方差与高光

对于固定仿射像素足迹，六个波模态在完整周期/相位上的未解析坡度协方差为：

`C = 0.5 * strength^2 * sum(A_i^2 * kappa_i * transpose(kappa_i) * (1 - F_i^2))`，其中 `kappa_i = 2*pi*k_i/128`。

迹 `trace(C)` 是平均未解析坡度方差；它对固定足迹的完整周期平均精确，**不是每个像素当前相位的精确局部方差**。独立的 37×41 直接梯度积分检查六组足迹/强度，[报告](validation/WATER_M2_slope_variance.json) 记录数值误差。强度 1 时的全未解析方差为 0.00131016468374505，并随强度平方缩放。测试函数 `slope_variance_audit()` 可复现，后续完整测试也会自动包含。

把它转换为高光/镜面反射瓣，还需要明确 BRDF、基础粗糙度及方向处理；M2 尚未实现。不能因为法线或颜色做了过滤，就宣称细碎高光已经稳定。此次没有改用归属缓冲的 alpha 通道。

## 提前跳过碰不到物体的反射线

在水面绘制前，新增的一道程序会为每块 8×8 像素记录最近的不透明表面深度。即使缺少颜色，已知的遮挡也算数。遇到不一致的深度或颜色，整块停用加速。反射线只有在能证明整段都位于遮挡物前方时才提前返回。可能命中物体、贴近分块角点或超出边缘覆盖时，仍用原有的逐像素追踪。1080p 的 R32F 双缓冲约增加 0.25 MiB。

在 Intel Iris Xe 的 [720p 水池计时](validation/WATER_M2_BOUNDS_720p.json)中，64 步反射合成从 32.780 毫秒降至 16.268 毫秒，生成深度分块另用 1.465 毫秒，整张输出逐字节一致。这组射线都未命中，干燥场景也可能承担分块开销。时间是单独绘制的中位数，其他并行显卡测试可能影响读数。用菜单里的“反射深度加速”即可切换对照。[逐射线与奇数窗口验证](validation/WATER_M2_BOUNDS_GPU.json)

Iris 从 deferred 阶段可提供不透明深度。[Iris 深度缓冲说明](https://shaders.properties/current/reference/buffers/depthtex/)
