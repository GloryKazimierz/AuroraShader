## 画面方向

水现在是开发的首要重点。目标是清楚可读的浅水、克制的青绿到靛蓝深水，
暖色夕阳碎光、冷色月光，以及与 Aurora 天空一致的倒影。
保留不同群系的水色特点，在光照与清澈度允许时看清水底。
判断标准覆盖运动过程和不同视角，不能只靠一张漂亮截图。

各项视觉线索必须协调：波纹改变的法线应同时服务于反射、折射与高光；
光线穿过更长的水路，背景应逐渐衰减；越贴近水面观察，反射应越明显。
艺术配色保持可调。开发继续自动推进，日常阶段无需用户逐一验收。
代码、知识与实际证据一起推送 GitHub 开发分支；保留 `main`、历史项目和现有
junction，项目与生成文件继续位于 D 盘。

## 现在的水实际做了什么

| 已有系统 | 当前范围 | 主要缺口 |
|---|---|---|
| M13 水面风格 | 流体识别、源颜色色调、随菲涅耳变化的解析天空色混合 | 原生 alpha 会继续削弱反射；没有场景倒影或完整水体合成 |
| M14 波纹 | 三组世界坐标锚定的解析坡度，扰动反射法线 | 没有流场、折射、轮廓位移或远处细节过滤 |
| M16 水深颜色 | 用同像素背景的竖直间距改变源色调，保留亮度 | 不是真实水路长度、吸收，也不会衰减透过来的背景 |
| 共用条件 | 效果受天空光、相机是否浸水、表面是否向上等条件限制 | 洞穴、水下和瀑布侧面需要各自明确的处理 |

[M13](MILESTONE_13.zh-CN.md)、[M14](MILESTONE_14.zh-CN.md) 和
[M16](MILESTONE_16.zh-CN.md) 已记录数值、编译或本机驱动检查。
这些记录没有把 Minecraft 水面观感标成已通过。当前解析水面反射仍不包含
天空极光、云与日月纹理。此前提议的 M20 Iris 预处理桥接**尚未实现**；
水体优先级已取代它。它仍可作为后续验证改进，不能记作已完成阶段。

## 优先顺序与依赖

下表是实现顺序，不是发布日期，也不保证一行只需一个提交。
先做可调试、可回退的完整小步，再增加额外装饰。

| 阶段 | 交付内容 | 依赖与完成时要回答的问题 |
|---|---|---|
| **W1——已实现，自动检查通过** | 在适用的距离雾步骤前，保存匹配的线性场景颜色和深度，明确写入／读取约定 | CPU／离线／本机检查在各自范围内验证了生产者约定与原输出保留。尚无消费者；真实 Iris 绑定／交换和 Minecraft 渲染仍未观察。快照本身还不是反射或透射。 |
| **W2——计划** | 共用的多尺度水面法线，按像素覆盖范围过滤细波纹 | 世界与时间连续；保留大尺度运动，过滤像素无法分辨的细纹。后续反射／折射／高光使用同一法线。几何位移等待岸边与剔除约定。 |
| **W3——计划** | 屏幕空间光线追踪反射、命中可信度与环境回退 | 依赖 W1 的颜色／深度匹配及 W2 法线。先单独验证命中，再平滑衔接失效区域，覆盖屏幕边缘、遮挡、细物体和移动镜头。 |
| **W4——计划** | 自己管理水体合成：菲涅耳反射／透射平衡、深度衰减与受保护的折射 | 依赖可靠场景输入和水面覆盖。替换原生源混合前，先定义水路估计、多层透明限制和雾的责任范围。 |
| **W5——计划** | 分开处理静水、定向水流与瀑布 | 优先使用已确认的流体输入，推断的流向明确标注；衔接顶面／侧面运动并固定岸边。全局滚动纹理不等于真实河流流速。 |
| **W6——计划** | 水下与穿越水面时的过渡 | 定义进出介质、水下衰减、表面背面和全反射；复用 W4 光传输，避免另叠一层无关滤色。 |
| **W7——计划** | 岸边／撞击泡沫、雨水响应、可选焦散 | 需要可信的接触、扰动／天气和接收面光照信息；只在信号支持的位置添加效果，不能每段岸边都永久套白边。 |
| **W8——计划贯穿各阶段** | 性能分档、兼容与艺术调校 | 实测 GPU 耗时及画面稳定性，再调整追踪步数、分辨率与过滤；保留有用的回退路径。 |

W3 可以先建立光线命中，但在 W4 改变合成前，仍必须明确原生 alpha 的限制。
未来水材质反射应与 Aurora 天空风格开关独立：天空可见性控制环境回退，
有效的局部场景命中使用自己的证据，不能因为关闭天空风格就一起消失。

## 光学模型与“光追”的范围

单个可见水面界面可以先按下面的设计草图理解：

```text
F = 菲涅耳（视线、法线、相对折射率）
T = exp(-RGB 消光系数 × 光线在水中的距离)
水面颜色 = F × 反射光 + (1-F) × (T × 背景 + 散射光)
```

这是设计草图，尚不是当前着色器公式，也不是完整路径追踪。
散射光需要由可用照明驱动，洞穴水不能凭空发亮。深度缓冲给出的间距只能估计
水填充的那段路径，夹着空气、多层水面或透明物体时尤其容易失效。
空气／水的折射率边界，以及从上方还是水下看向界面，都影响折射与全反射。
[介质光学](https://www.pbr-book.org/4ed/Reflection_Models/Specular_Reflection_and_Transmission)、
[反射与透射](https://www.pbr-book.org/4ed/Reflection_Models/Dielectric_BSDF)、
[透射衰减](https://www.pbr-book.org/4ed/Volume_Scattering/Transmittance)。

SSR 沿光线查询当前可见的屏幕深度。屏幕外或被遮住的几何体没有记录，
未命中时必须有明确回退和平滑可信度过渡；它不代表完整场景。
[屏幕空间追踪及其限制](https://casual-effects.blogspot.com/2014/08/screen-space-ray-tracing.html)。
世界空间体素追踪还需要新的场景表示、更新、内存和材质约定。
硬件光追／路径追踪需要另行确认渲染器接口与加速结构支持，当前仓库没有这些设施。
能使用计算着色器，并不能证明已经能做硬件光追。
[Iris 程序阶段](https://shaders.properties/current/reference/programs/overview/)。

## 可重复的观察矩阵

每组 A/B 对比固定种子／位置、镜头路径、FOV、分辨率、曝光、时间与天气。
有实际测试环境时使用单独的 D 盘配置，保留历史世界与 junction。
结果留空代表**没有观察**，不代表通过。

| 场景／视角 | 必须判断的现象 | 实际观察结果 |
|---|---|---|
| 浅、中、深平底池；垂直俯视 | 水底可读性、逐渐衰减、群系水色，不出现无来源发光 | |
| 同一水池，视线与表面法线夹角 0°／30°／60°／80° | 菲涅耳平滑变化，反射与透射平衡，地平线表现 | |
| 绕行／平移镜头，在同一位置改变 FOV | 波纹固定于世界，倒影几何关系正确，不贴着屏幕游动 | |
| 近、中、远距离水面 | 近处看清细纹，远处平滑减少细节，地平线不闪烁／频闪 | |
| 河道弯曲、浅台阶与含水边界 | 下游方向可信，接缝稳定，水体分类正确 | |
| 瀑布顶缘、垂直水帘与落点 | 向下流动与平面水不同，侧面覆盖保留，扰动／泡沫集中在合理位置 | |
| 斜岸、悬崖、细杆与栅栏 | 不透视岸边、不误命中、不拉长倒影，也没有永久白边 | |
| 倒影物体进出屏幕、被前景挡住 | 可信度与回退连续，不出现黑洞或突然整块消失 | |
| 正午、夕阳、满月／新月、雨和雾 | 高光、天空身份与光照强度协调，不变成过曝白水 | |
| 镜头穿越水面，从水下向上看 | 介质过渡连续，折射窗口与全反射可信 | |
| 火把洞穴水池；水边玻璃、粒子、实体与手持物 | 局部照明、透明排序正确，没有手形深度／倒影瑕疵 | |
| 其他群系／资源包 alpha、窗口尺寸与画质预设 | 材质意图稳定，没有旧帧缓冲残留，回退与成本有记录 | |

## 每轮迭代留下什么证据

1. 检查公式与不变量：有限亮度、权重／能量上界、精确关闭路径、坐标稳定与有效光线区间。
2. 编译受影响选项，用合成 GPU 输入检查命中、失效、边缘、异常深度和合成，并记录覆盖边界。
3. 有真实测试配置时，采集上述 Minecraft 固定场景与短运动序列，在游戏里判断观感、排序和时间瑕疵。
4. 写明硬件／分辨率／设置，实测 GPU 成本后再划分画质档。工具耗时与单独着色器成功不是游戏 FPS 证据。
5. 把代码、观察结果、未解决案例和下一步一起发布，继续推进。

波浪参数需要联系波长、幅度和速度；大尺度几何运动与细法线纹理的采样限制不同。
[波浪模型参考](https://developer.nvidia.com/gpugems/gpugems/part-i-natural-effects/chapter-1-effective-water-simulation-physical-models)。
第一项结构性交付是 W1 的可信场景／深度输入，让后续反射和透射可以审查，
避免把不同深度或雾空间混在一起。
