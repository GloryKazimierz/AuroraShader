# Chapter 1: GPU Rendering Pipeline

## 1. The core mental model

A renderer converts structured scene data into pixels. A simplified real-time
pipeline is:

```text
CPU / application
-> draw or dispatch commands
-> vertex processing
-> primitive assembly
-> clipping
-> rasterization
-> interpolation
-> fragment/pixel shading
-> depth/stencil tests
-> blending
-> render target
-> post-processing
-> presentation
```

The exact API differs between OpenGL, Vulkan, Direct3D and Metal, but this mental
model remains useful.

## 2. CPU work versus GPU work

The CPU normally prepares resources and commands:

- create/update buffers and textures;
- bind or reference pipelines/materials;
- submit draw/dispatch work;
- organize scene traversal and culling.

The GPU performs massively parallel work over vertices, primitives, fragments,
compute invocations and memory operations.

A common interview mistake is to say "the GPU renders everything" without
separating command submission from shader execution.

## 3. Vertex stage

A vertex shader usually transforms vertex attributes and produces values to be
interpolated across the primitive.

Typical input:

- position;
- normal;
- UV;
- tangent;
- color;
- skinning data.

Typical position transform:

```text
clipPosition = Projection * View * Model * localPosition
```

The vertex shader does not usually produce final screen pixels. It produces the
vertices of transformed primitives.

## 4. Primitive assembly and clipping

Vertices are assembled into triangles, lines or points.

Triangles outside the clip volume are discarded or clipped. The important
concept is that clipping occurs before rasterization so invalid geometry does not
turn into arbitrary screen fragments.

The clip-space position is homogeneous: `(x,y,z,w)`. Perspective division later
produces NDC:

```text
ndc = clip.xyz / clip.w
```

## 5. Rasterization

Rasterization answers:

> Which screen samples/pixels are covered by this triangle?

For each covered fragment, the rasterizer interpolates vertex outputs such as UVs,
colors, normals or custom varyings.

This is where continuous triangle geometry becomes discrete screen samples.

## 6. Fragment shading

A fragment shader computes candidate outputs for covered fragments.

It may:

- sample textures;
- evaluate lighting;
- read G-buffer or shadow data;
- discard fragments;
- output one or multiple render targets.

A fragment is not guaranteed to become a final pixel. Depth/stencil tests and
other operations can reject it.

## 7. Depth/stencil and blending

Depth testing determines whether a fragment is in front of previously stored
geometry.

Blending combines a fragment with existing render-target content, commonly for
transparency.

These are conceptually different:

- depth asks whether the fragment should survive;
- blending asks how surviving color combines with the destination.

## 8. Render targets and multiple passes

Modern rendering is rarely one pass.

A frame may contain:

```text
shadow pass
-> geometry/G-buffer pass
-> deferred lighting
-> transparency
-> post-processing
-> UI
-> present
```

AuroraShader already demonstrates this multi-pass structure.

## 9. Graphics pipeline versus compute pipeline

A graphics pipeline contains fixed-function stages such as rasterization and
depth testing.

A compute shader is more general:

```text
dispatch workgroups
-> execute arbitrary parallel shader work
-> read/write buffers or images
```

Compute does not automatically rasterize triangles. If you implement rasterization
in compute, you must explicitly build the missing behavior yourself.

This distinction is important for your future Vulkan renderer research.

## 10. OpenGL versus Vulkan mental model

OpenGL hides more state management and driver work.

Vulkan makes more of the execution model explicit:

- command buffers;
- pipeline objects;
- descriptor sets;
- synchronization;
- resource layouts;
- render passes/dynamic rendering;
- explicit queues.

The underlying GPU ideas are similar; Vulkan exposes more responsibility to the
application.

## 11. Common interview questions

### What does rasterization do?

It converts projected primitives into covered fragments/samples and interpolates
per-vertex data for those fragments.

### Is a fragment the same as a pixel?

Not exactly. A fragment is a candidate contribution generated by rasterization.
It may fail depth/stencil tests, be discarded, or contribute to a multisampled
pixel.

### What is the purpose of the vertex shader?

To process per-vertex data, most importantly producing clip-space position and
varyings for interpolation.

### Graphics versus compute?

Graphics provides a specialized primitive/raster pipeline; compute provides
general parallel execution without automatic rasterization.

```text
vertices -> triangles -> clip -> rasterize -> interpolate -> shade fragments
-> depth/blend -> render target -> later passes -> final image
```
