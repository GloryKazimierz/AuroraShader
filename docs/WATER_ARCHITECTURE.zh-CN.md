# Aurora 水体架构：先明确职责，再增加效果

更新日期：2026-11-21。[English](WATER_ARCHITECTURE.md) · [水体路线图](WATER_ROADMAP.zh-CN.md)。

AuroraShader 将水体渲染划分为五层，并用 A–L 模块记录各自输入、输出与边界。
这些是目标架构，不代表所有功能已经完成。W1 匹配快照、W2 过滤法线、W3 有范围
限制的 SSR 已有自动／本机证据；[W3](WATER_03_SCREEN_REFLECTIONS.zh-CN.md)
仍保留原生 alpha 和暂缺反射段雾的限制。本阶段是 **水体 M0／W4A**，分支
`codex/water-04a-optics-foundation`；完整历史 CPU／专项离线／本机检查已通过。以下水体 M0–M7 是新序列，
与历史整包 M1–M19 分开编号。

## M0 当前实现与可观察数据

`WaterParams` 只有三个实际使用的字段：`reflectionF0=0.02` 用于原有生产路径
菲涅耳函数；`worldBlockMeters=1.0` 与 `debugGapRangeMeters=16.0` 用于间距调试。
没有填入尚未使用的吸收、IOR 或群系参数占位；F0 仍是已有水类反射的艺术近似。
`water_debug_capture.glsl` 在 water 程序记录数据，`water_debug_view.glsl` 在 final 显示；
现有位置重建辅助函数继续共用，没有新水体合成阶段。

| DEBUG_VIEW | 含义 | 不能据此断言 |
|---|---|---|
| 7 | 通过有效性与前景深度检查的水面为白，其余黑 | 不是完整水体体积或所有被遮住水层 |
| 8 | 过滤后的观察空间法线，以 N×0.5+0.5 显示；+Z 偏蓝 | 没有几何波浪、瀑布流场或粗糙度模拟 |
| 9 | 同像素水面到背景沿视线间距，0–16 米映射为灰度；无效背景为洋红 | 不是真实水体厚度、折射光程或已实现吸收 |

诊断覆盖被分类的水面各面；只有原始朝上程度允许细波纹扰动，侧面不被伪装成河流。
仅 7／8／9 使用全分辨率 `colortex7 RGBA32F`：RGB 为有符号单位观察空间法线，
A 为水面原始窗口深度，零法线是无效清空值。它不是颜色 alpha。
只关闭该数据附件的混合；场景颜色仍走原生混合。
water 写 main 侧，final 读取该侧；M0 没有全屏阶段写 colortex7，因此不增加
显式 flip 覆盖，每帧清空。

final 先将有界窗口 UV 映射为源纹理像素，并用其中心重建，因此窗口与源纹理可以
分辨率不同。它将捕获深度与 `depthtex0` 比较，容差为一个 D24 量化单位
`1/16777215`；尺寸、有限性、法线长度及深度不符时显示黑色。
模式 9 从 `depthtex2` 重建背景，再把差向量变换到世界空间测长，按项目的
“一方块视为一米”约定显示。共面表面与后来不写深度的覆盖仍有歧义；
`depthtex2` 表示捕获时刻，不是任意场景下真实的水体出口。
普通模式及旧调试 0–6 的原行为必须保留；M0 专项数值／本机检查已通过。
实际 Iris 绑定／交换、Minecraft 画面和性能均未观察。

## 五层职责与真实绘制顺序

| 层 | 负责内容 | 必须明确的边界 |
|---|---|---|
| Common／WaterParams／光学 | 单位、有限参数、颜色空间、界面菲涅耳、消光和共用坐标函数 | 艺术倍率与物理量分开，说明哪些字段真正参与计算 |
| 模拟 | 高度／位移、斜率、方差、速度、Jacobian 与可选持久状态 | 世界锚点、更新节奏、边界、种子、能力和内存限制 |
| 表面采集 | 水面分类、覆盖、深度、法线、材质／介质及有效背景关系 | 玻璃／粒子／排序、手部深度、侧面及缺失层 |
| Composite 光学 | 反射／透射、有效光线命中、分段衰减、散射、泡沫与介质合成 | 每段路径和每份光照只由一处负责；无效输入有回退 |
| 后处理 | 实现后的时间重建、辉光、曝光与显示变换 | 历史拒绝与曝光约定，不能再次重复水体消光 |

Iris 的阶段顺序不能互换：

```text
setup（载入／尺寸变化；仅 compute，可选）
begin（阴影之前；需要影响投影物时在此更新模拟）
shadow -> shadowcomp -> prepare（阴影之后、世界 gbuffers 之前）
世界 gbuffers -> deferred／W1 快照 -> 后续透明 gbuffers
composite 链（未来自主管理的水体光学，再到后处理）
final -> 窗口 backbuffer
```

[Setup](https://shaders.properties/current/reference/programs/setup/) 不是逐帧更新。
[Begin](https://shaders.properties/current/reference/programs/begin/) 可向阴影投影物
提供当前波浪；[prepare](https://shaders.properties/current/reference/programs/prepare/)
不能追溯修改已经画完的本帧阴影。[Composite](https://shaders.properties/current/reference/programs/composite/)
位于 gbuffers 之后；[final](https://shaders.properties/current/reference/programs/final/)
只输出窗口，不能当作颜色附件历史写入阶段。

当前 W3 着色仍在水面片元辅助函数内，迁移到 composite 属于后续工作。
现有 composite／composite1／composite2／composite3 分别做辉光提取、横向模糊、
纵向模糊和 HDR 加和；只有 final 做曝光／色调映射／显示编码／调色。
目前没有 FFT、计算着色器波浪模拟或 TAA。未来水体合成必须位于辉光提取之前，
明确重排阶段并保留原输出；历史不能依赖 final 回写。

## 共用数据与接口约定

- 光学和波浪模型采用世界空间 **1 方块视为 1 米** 的标定。每个变量注明空间；
  观察空间 z 差不是沿光线距离，竖直间距也不是折射后的水中路径。大世界整数锚点
  与局部浮点分开保存。
- 亮度和光传输使用场景线性 HDR，最后只编码一次显示颜色。吸收／散射系数为非负
  每米量，IOR 为正数，风包含方向与速度。拒绝非有限输入，并为参数协议记录版本。
- 目标 WaterParams 从已确认可用的群系／天气输入映射吸收、散射、IOR、浑浊度、
  风、海况和粗糙度。缺少真实群系或流速数据时声明默认／推断，不冒充测量值。
- **采样反射亮度之前**先处理过滤后波纹方差与泡沫粗糙度。SSR 可信度表示数据
  可靠性，不是菲涅耳反射率。倒影里的太阳盘与另算的太阳高光不能重复计能。
- 保留低成本解析路径和有边界的场景数据路径；SSR 缺失时回退到可用环境。
  暗洞不能因追踪失败得到室外天空。当前 W3 配色回退还没有真实极光、云、光晕或日月盘。
- gbuffers_water 同时绘制其他透明地形。全局关闭混合或最终补偿不能自动保留
  玻璃／水／粒子的叠层。替换原生合成前先约定覆盖、排序、源 alpha 与不支持情况。
  [Iris gbuffers](https://shaders.properties/current/reference/programs/gbuffers/)、
  [混合控制](https://shaders.properties/current/reference/shadersproperties/rendering/)。

## 计划中的 composite 流程

M0 尚未执行这个合成器。目标流程明确每一步的负责人：

```text
验证前景水面记录与叠层策略；无效则走已声明回退
→ 判断眼点／近平面介质及首界面，尽早分开水上／水下
→ 读取 WaterParams、过滤法线方差、泡沫覆盖与有效粗糙度
→ 深度验证折射／接收面，拒绝前景穿越、缺失及未支持层
→ 水底直射光：入射水路透射率 × 有界焦散通量 × 直射光
  （需要分开的直射输入，不能对已经照明的快照 RGB 再乘一次入射吸收）
→ 出射透射亮度＋由照明驱动的入散射／有界浪尖响应
→ 按粗糙度取反射亮度：SSR → 可用探针／天空；命中到界面路径只算一次
→ 菲涅耳分配反射／透射；泡沫按覆盖率混合自己的有界响应
→ 剩余界面到眼点的介质／大气段只算一次
→ 自主管理的线性 HDR 合成 → 未来可选 TAA → 现有辉光 → 最终显示
```

反射可信度只在反射分支内混合数据来源，不替代菲涅耳，也不额外增加一份满强度太阳。
介质分支先给每段空气／水路径明确归属。未支持叠层回到声明的近似／回退，不能虚构
一个水体出口。接收面的入射直射光段与观察方向的出射段必须分别处理。

## A–L 模块约定

下表记录目标，并明确已有部分。

| 模块 | 输入 → 负责的输出 | 依赖／边界 |
|---|---|---|
| A 参数 | 群系／天气／海况 → 共用 WaterParams | M0 先做实际使用的基础字段；环境映射必须有可用输入 |
| B 波浪 | 时间／世界锚点／风 → 高度、法线、方差、Jacobian | W2 目前只有过滤法线细节；噪声、Gerstner、FFT 与网格位移分别规划 |
| C 采集 | 水面分类＋匹配场景深度 → 有效水面记录 | M0 先做诊断；单个可见层不能描述所有透明重叠 |
| D 折射 | 界面／IOR＋背景深度 → 经深度验证的透射样本 | 拒绝前景穿越与屏幕缺失；UV 扭曲单独标为近似，色散可选 |
| E 光传输 | 入射光段＋出射观察段 → 衰减亮度和入散射 | 每段水路只计一次；浪尖 SSS 是有界近似，不是无来源发光 |
| F 反射 | 粗糙度／法线＋场景／探针／天空 → 反射亮度 | W3 SSR 已有；探针、共用天空、Cox–Munk 海面统计斜率仍待实现并匹配波纹方差 |
| G 泡沫 | 压缩 Jacobian／接触／历史 → 泡沫覆盖与粗糙度 | 岸边深度不等于湍流；历史需要平流、衰减和拒绝，不做永久岸边白线 |
| H 焦散 | 水面／光映射＋接收面 → 聚焦后的水底直射光 | 面积比／阴影空间方法需覆盖范围和通量归一；随深度变宽并限制奇异增益 |
| I 水下 | 相机介质＋逐样本近平面／首界面 → 水线、斯涅尔窗口和体积 | 仅相机标记不能切开画面；不透明遮挡、绕序和局部波高都重要 |
| J 交互 | 已确认事件／流向 → 波纹、尾迹、雨与定向流动 | 输入的速度／事件与推断滚动分开；不假定能读取游戏物理或全部事件 |
| K 稳定性 | 法线方差、运动、深度／材质 → LOD、粗糙度与有效历史 | 仅重投影不够；拒绝新显露、介质／法线／深度变化和陈旧模拟 |
| L 奇幻 | 明确可选控制 → 生物荧光、潮汐、彩虹、镜头雨滴 | 艺术自发光与散射分开；雨滴状态属于相机，潮汐需世界／几何规则 |

两段光传输需要明确光照归属：焦散修改水底的**直射光，然后才做出射衰减**。
W1 RGB 已经照明；再次统一乘入射吸收会连环境光等其他成分一起改动。
应分出直射分量，或者明确标为近似，不能把入射段悄悄重复计算。
[透射衰减](https://www.pbr-book.org/4ed/Volume_Scattering/Transmittance)。

透视光线共享同一个眼点。逐像素水线关注每个近平面样本的介质和首次穿越界面，
不是给每条光线虚构不同的相机介质。折射与全反射之前，需要有效的水面／不透明
深度关系和一致的界面正反侧。
[介电质反射／透射](https://www.pbr-book.org/4ed/Reflection_Models/Dielectric_BSDF)。

## 缓冲职责、交换与生命周期

| 资源 | 当前写入者 → 读取者 | 分辨率／生命周期 |
|---|---|---|
| colortex0 RGBA16F | 场景／deferred／后绘制混合／辉光加和 → 后续场景阶段／final | 显示分辨率；HDR 场景，不是水体历史 |
| colortex1 RGBA16／2 RG16 | 受支持不透明材质 → deferred／调试 | 显示分辨率；编码法线／有效性与光照等级，每帧清空 |
| colortex3／4 RGBA16F | 现有辉光阶段 → 下一辉光阶段 | 宽高各一半；临时数据，不能同时充当持久水体历史 |
| colortex5 RGBA16F／6 R32F | W1 deferred → W3 水面 | 显示分辨率；配对的雾前照明 RGB／有效性和深度，每帧清空 |
| depthtex1／depthtex2 | Iris 深度捕获 → 有保护的读取方 | 显示分辨率；由捕获时刻定义，不能随意互换或在此声称写入权 |
| M0 colortex7 RGBA32F | water 诊断采集 → final 调试 | 仅调试 7–9；全分辨率、零清空；法线 xyz＋原始深度 w，不持久 |
| 未来模拟／历史 | 单一明确生产者 → 指定后续读取者 | 专用世界网格或屏幕分辨率，不复用仍存活的辉光／快照内容 |

Gbuffers 写 main 侧；全屏阶段通常读 main、写 alternate，再交换发布。
每次覆盖都记录生产／消费侧、清空边界和显式 flip 设置，不能边读边写同一张图像。
W1 的真实 Iris 交换集成仍未观察，本机合成检查不代替这一步。
[Iris 缓冲](https://shaders.properties/current/reference/buffers/colortex/)、
[交换规则](https://shaders.properties/current/reference/shadersproperties/rendering/)。

名义分配量为宽 × 高 × 每像素字节 × 实际侧数，再加 mip、各级联及历史字段。
W1 的每像素 8＋4 字节、双侧全尺寸，在 1920×1080 下约为 47.46 MiB；
M0 RGBA32F 调试附件若双侧分配，另需约 63.28 MiB。都不含场景／深度／阴影／
辉光及驱动开销，也没有测量 Iris 在非调试模式的实际分配行为。
模拟网格按自身尺寸计费，而非窗口尺寸；增加字段前先写资源账本。

### 未来资源账本——建议格式，尚未分配绑定

以下是分配量示例，不是已经选定的网格尺寸或实测显存。N=256 表示一层模拟级联，
S=1024 表示一张光空间图；屏幕估算用 1920×1080。先确认存活区间与硬件能力，
再分配实际附件／image 编号。

| 建议字段／格式 | 生产者 → 消费者 | 生命周期／尺寸／名义示例 |
|---|---|---|
| 位移 xyz＋标量 Jacobian，每级 RGBA16F | 必需的阴影／采集之前更新模拟 → 网格、阴影、泡沫／焦散输入 | N²；需要上一状态几何时双状态，每级 N=256 为 1.00 MiB |
| 编码法线 xy，每级 RG16F | 模拟导数 → 采集／着色 | N²，双状态预算 0.50 MiB，重建单位法线；可选方差 R16F 再加 0.25 MiB |
| 泡沫 R8 或 R16F ping-pong | 压缩／接触＋前帧泡沫 → 着色／下次更新 | 持久 N²，N=256 为 0.125／0.25 MiB，必须有平流／衰减／重置 |
| 涟漪高度／速度 RG16F ping-pong | 有界交互更新 → 波浪合并／下次更新 | 持久 N²，N=256 为 0.50 MiB，明确事件／边界／网格间距限制 |
| 焦散通量 R16F 或 RGBA16F shadowcolor／自定义 image | 水面／光映射 → 水底直射光 | 逐帧 S²，S=1024 单侧为 2／8 MiB；额外过滤／历史另计 |
| 半分辨率反射 RGB／可信度 RGBA16F | 有边界 SSR 阶段 → 水体合成 | 临时、宽高各半，1080p 双侧预算 7.91 MiB；W3 当前没有此缓冲 |
| 运动 RG16F | 当前／先前真实几何变换 → 时间拒绝 | 全屏，单侧 7.91 MiB；只算相机运动无法描述动画水面 |
| HDR 历史 RGBA16F＋深度 R32F＋法线 RG16F＋标记 R8 | Composite 历史负责人 → 下一帧时间阶段 | 全屏 ping-pong，示例共 67.24 MiB；同时记录曝光／介质／材质有效性 |

一张 RGBA16F 不能同时容纳位移 3＋法线 2＋Jacobian 1。上述拆分在方差及侧数
之前是每像素 12 字节。也可从导数重建法线，但读取／过滤成本不同。
标量行列式也不能替代后续算法所需的完整 Jacobian 各分量。
FFT 复数频谱／临时数据、mip、探针、体素与体积网格均是额外分配，不包含在表内；
不能偷偷复用仍存活的辉光 3／4 或快照 5／6。
已测试本机上下文提供八个同时绘制缓冲／颜色附件，但这不证明未来账本能一次塞入
同一阶段或 Iris 加载器。分配绑定前确认同时存活输出、sampler／image 单元和格式支持。

当前没有水体时间历史。未来负责人必须在包重载、窗口／缩放变化、维度／世界切换、
相机跳变／传送、模拟锚点／种子／网格变化、不兼容设置或时间突变时使历史失效。
逐样本拒绝深度／法线／材质／介质不符、新显露及越界重投影。读取前初始化双侧，
保存上一帧变换、曝光约定和世界原点；衰减使用经过时间，而非帧数。

### M1 首版水体合成的候选存储

池底每个有效像素只需记录本包直射光占总照明的比例。设现有池底线性颜色为
`L`、直射比例为 `q`、入射和出射两段的 RGB 透射率分别为 `Ti` 与 `Tv`，
池底传回的颜色为 `Tv * (L * (1-q) + Ti * L * q)`。水中入散射还需要单独的
照明来源。洞穴里若 `q=0`，入射太阳光这一段不会削弱火把颜色。从池底到眼睛
的水路仍会衰减火把的光。

候选布局用 RG32UI 保存八面体法线和水面深度的原始位，用 R8 记录透明层交叠，
用 R16F 存直射比例。−1 表示数据缺失，0 表示有效但没有本包直射光。
1080p 双侧缓冲按每像素 11 字节计算，预计比 W1 多 43.51 MiB，前提是水面能在
deferred 之后复用 colortex2 记录光照等级。启用前须在实际混合格式目标上核验
整数初始化、深度逐位回读、透明物体前后两种顺序及回退像素。M0 调试仍使用自己的缓冲格式。


## 水体 M0–M7 顺序

| 阶段 | 交付内容 | 当前状态／验收问题 |
|---|---|---|
| M0／W4A | 共用函数、WaterParams 基础、水掩码／过滤法线／沿光线间距调试 | 已实现，完整历史 CPU／专项离线／本机检查通过；要求默认场景不变、采集数据可独立观察 |
| M1 | 入射／出射两段消光与入散射，响应深度和太阳 | 计划；先定义直射／环境光归属、水路与合成，再增加颜色 |
| M2 | 方差／LOD／环境回退 | 计划；远水平静，有顶水池不出现室外天空 |
| M3 | 深度验证折射与逐像素水线／斯涅尔窗口 | 计划；覆盖前景／重叠／近平面／内外介质 |
| M4 | 投影焦散，从浅水清晰到深水柔和 | 计划；有限通量，放在水底直射光的正确阶段 |
| M5 | Jacobian／接触／历史泡沫与衰减 | 计划；真实支持的压缩／接触及时间生命周期 |
| M6 | 多级联 FFT 与海况 | 计划；先确认能力、级联重叠／能量、世界锚定和内存 |
| M7 | 交互与可选奇幻表现 | 计划；只增加可用事件输入，效果各自可配置 |

这份新序列细化此前 W4–W8，不改写 W1–W3 证据或历史里程碑编号。
物理、艺术与调试控制应分组。M0 只扩展现有调试选择器，没有未使用滑块，
也没有把下方未来画质档位当成已经发布。

## 建议的画质路径与预算

| 建议档位 | 目标路径 | 能力／工作量边界 |
|---|---|---|
| Low | 解析天空、噪声法线、可选 UV 扭曲与简化雾 | 基础光栅路径，零 SSR 查询；UV 扭曲不等于已验证折射 |
| Medium | Gerstner、SSR、步进折射、程序焦散、Jacobian 泡沫 | 以当前 SSR 最多处理 64 格为起点；折射／焦散预算待测 |
| High | 两级 FFT、探针、色散、阴影空间焦散、历史、体积 | 确认 compute／image 能力、持久存储与带宽；当前 128 格 SSR 只是候选预算，不是已实现档位 |
| Ultra | 三／四级 FFT、体素或受支持 RT、色散焦散、尾迹 | 新场景表示或已确认加速后端；当前 GLSL330 包没有硬件光追 |

配置只有一套优先顺序：**能力限制 > 水体总开关关闭 > 所选档位与明确模块覆盖**。
档位提供默认，用户对模块的明确覆盖只能在前两项允许的范围内替换该默认。
即“有效开启 = 受支持 AND 总开关开启 AND 请求开启”。不支持的 FFT／探针／RT
保持关闭并显示明确回退；选 Ultra 不会安装后端，也不能悄悄开启不可用模块。
界面应显示有效值和回退原因。调试观察与正常画面的功能开关分别处理。

计算能力需与当前 GL3.3 验证上下文分开确认。FFT 网格、折射步数、探针更新频率和
历史缓冲仍属预算决策，不是现有默认。不能靠一个名称或新增计算着色器就声称硬件光追。
[Khronos 光追要求](https://docs.vulkan.org/guide/latest/extensions/ray_tracing.html)。

一个**暂定项目目标**是：在已命名的 Intel Iris Xe 测试 GPU、1920×1080、Medium 下，
水体额外 GPU 时间中位数不超过 2.0 ms、p95 不超过 3.0 ms；这不是测量结果。
相对明确的匹配基线测差值，注明是否包含快照成本，并记录驱动、频率、覆盖率、
分辨率和所有设置。预热后测 GPU 时间，不能拿验证工具耗时当帧耗时。
发布画质档前按实测修订目标。现有 Balanced／Light／Soft Shadows 仍是七项控制预设，
不是这四个新档位。
