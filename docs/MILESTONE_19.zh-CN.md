# Milestone 19：暖色太阳与冷色月亮天空光晕

日期：2026-11-13。分支：`codex/milestone-19-celestial-glow`。
基线：M18 提交 `60871f45b7e84e331bacaf541874c7ae4df86090`。
[English learning notes](MILESTONE_19.md)。

M19 只在天空背景中，给太阳周围添加暖色光晕，给月亮周围添加更克制的蓝色光晕。
原有天体纹理继续独立绘制。这是艺术化天空效果，不新增地形照明，
也不模拟物理大气散射。默认值尚未在 Minecraft／Iris 中评价观感。

## 1. 控制项与管线位置

已有的 **Aurora 天空与光照**页面新增：

| 选项 | 默认值 | 可选值 |
|---|---|---|
| `CELESTIAL_GLOW` | 1 | 0：关闭，1：开启 |
| `SUN_GLOW_STRENGTH` | 0.4 | 0、0.2、0.4、0.6、1 |
| `MOON_GLOW_STRENGTH` | 0.15 | 0、0.05、0.15、0.3、0.5 |

单项强度为零只关闭对应天体的光晕。总开关关闭或两项强度均为零时，
精确保留 M18 的天空输入。功能要求线性 HDR 模式、Aurora 天空风格、
正常绘制，以及大于零的天空混合／环境权重。

`applyCelestialGlow(rayView, scene)` 仅在 `MC_RENDER_STAGE_SKY` 调用：

```text
已有天空配色 -> 日月光晕 -> 已有夜间极光 -> 场景颜色
已有太阳／月亮／星星继续走各自的绘制路径
场景合成 -> 已有泛光 -> 曝光／高光映射／显示输出
```

没有新增阶段、附件或采样器。alpha、原版天体纹理、星星、
虚空／日落阶段、共享雾配色、云源颜色及水反射配色保持不变。
已有泛光可能扩散足够亮的天空像素；它仍是独立的图像处理功能。
[Iris 阶段挂钩](https://github.com/IrisShaders/Iris/blob/99d855970316329f2e0e42ac2b79ef763cb77cc3/common/src/main/java/net/irisshaders/iris/mixin/MixinSkyRenderer.java)。

现在共有 57 个控制项，每种语言 179 个键。新增三项不属于原有七项质量预设；
选择预设会保留它们及原有另外 47 个非预设控制项，共保留 50 个值。

## 2. 为什么角度光晕能跟随天空

设 `r` 为归一化视线，`b` 为归一化天体方向。
两者点积等于 `cos(theta)`，其中 `theta` 是夹角：

```text
c = clamp(dot(r, b), -1, 1)
A(c) = 0.75 * exp(-(1 - c) / 0.012)
     + 0.25 * exp(-(1 - c) / 0.08)
```

较窄部分形成更亮的中心，较宽部分提供柔和尾部。两者都随离开天体方向
而平滑减弱，无需计算反余弦。中心值为 1，整个函数保持在 [0, 1] 内。

它的宽度固定在天空角度中。改变视野范围或图像分辨率后，
像素占用会自然变化，并不是固定屏幕半径的圆。
旋转相机时，两条方向一起旋转，点积保持不变。
这与对已经绘制的图像进行模糊的泛光不同。

着色器分别使用 Iris 提供的视图空间 `sunPosition` 与 `moonPosition`。
不会把太阳取反来虚构月亮，也不使用会切换当前投影天体的
`shadowLightPosition`。
[Iris 世界参数](https://shaders.properties/current/reference/uniforms/world/)。

固定版本的 Iris 实现分别采样 `SUN_ANGLE` 与 `MOON_ANGLE` 环境属性。
保持方向独立，也就不必假定所有受支持天空中的日月都恰好相反。
[天体参数实现](https://github.com/IrisShaders/Iris/blob/99d855970316329f2e0e42ac2b79ef763cb77cc3/common/src/main/java/net/irisshaders/iris/uniforms/CelestialUniforms.java)。

## 3. 地平线、雨天与月相

设归一化上方向为 `u`，权重如下：

```text
rayHorizon = smoothstep(-0.025, 0.04, dot(r, u))
bodyHorizon = smoothstep(-0.08, 0.04, dot(b, u))
dry = 1 - clamp(rainStrength, 0, 1)
common = clamp(SKY_BLEND, 0, 1) * environment * dry^2 * rayHorizon
sunAdd = common * sunStrength * sunHorizon * A(dot(r, sun)) * (1, 0.62, 0.28)
moonAdd = common * moonStrength * moonHorizon * A(dot(r, moon))
          * moonPhaseWeight * (0.24, 0.38, 1)
result = scene + sunAdd + moonAdd
```

每个天体由自己的高度控制地平线淡出；月亮没有从太阳推导的夜间开关。
雨会平滑减弱两种光晕，全雨强度时为零。已有环境保护会在有天花板／
无天空光维度、相机处于流体，以及强失明／黑暗效果下抑制新增功能。

`moonPhase` 是 0–7 的整数，其中 0 为满月，4 为新月。
[Iris 月相约定](https://shaders.properties/current/reference/uniforms/world/#moonphase)、
[月相绑定](https://github.com/IrisShaders/Iris/blob/99d855970316329f2e0e42ac2b79ef763cb77cc3/common/src/main/java/net/irisshaders/iris/uniforms/WorldTimeUniforms.java)。

M19 使用艺术化曲线 `P = (1 + cos(2*pi*phase/8)) / 2`，
并精确保留满月／新月端点：

| 月相编号 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 权重 | 1 | 0.853553 | 0.5 | 0.146447 | 0 | 0.146447 | 0.5 | 0.853553 |

这只是光晕亮度选择，不是 Minecraft 的光照等级表、月亮纹理重建或物理月球
照明计算。它不改变月相图案、地形月光，也不在月相编号之间插值。

## 4. 上界与回退

两种颜色向量的分量均非负且不大于 1。光晕／保护权重不大于 1，
太阳强度最多 1，月亮强度最多 0.5，所以新增 RGB 的每个分量都不超过 1.5。
默认强度对应保守上界 0.55。这些是新增场景线性颜色的上界，不是显示亮度实测值。

所需方向会在归一化前检查，并通过缩放避免溢出。
所需运行时输入无效，或结果为负、非有限数、超过半精度浮点有限上限 65504 时，
新增辅助函数会返回原场景。它不会修复原本已经无效的场景颜色。

太阳方向无效只关闭太阳贡献；月亮方向或月相无效只关闭月亮贡献。
这让独立输入互不拖累。关闭、两项强度为零、旧模式、调试、
Base-330 天空、零天空混合或零环境贡献时，精确保留输入场景。
单个天体落到地平线淡出范围外，也不会改变另一个天体的贡献。

暖／冷 RGB 和地平线淡出均为艺术化选择。
没有大气密度积分、体积阴影、镜头鬼影、地形光源或新的天体纹理反射。
成本是额外的天空片元计算，没有声称实测 FPS 结果。

## 6. 学习问答

1. **为什么用点积？** 归一化方向直接提供夹角信息，不需要投影或反余弦。
2. **为什么叠加两部分？** 在有界形状中分别形成较窄中心和较宽尾部。
3. **为什么日月方向独立？** 阴影选择或太阳取反不能完整代表两个实际天空输入。
4. **为什么变焦会改变大小？** 固定天空角度在不同投影下占据不同屏幕面积。
5. **为什么不把光晕加到雾里？** 它处理天空背景，不是共享物理散射模型。
6. **为什么保留原版天体？** 原纹理与月相轮廓已有独立绘制路径。
7. **为什么要求精确回退？** 关闭功能可以可靠地与 M18 对比。
8. **驱动测试能证明什么？** 给定输入的数值执行，不是 Iris 绑定、绘制顺序或真实世界。
