# Water 02：按像素范围过滤的多尺度水面法线

日期：2026-11-21。分支：`codex/water-02-filtered-waves`。
基础：W1 提交 `5d3e91761beaa3747052c11aa429e27be8d42df4`。
[English notes](WATER_02_FILTERED_WAVES.md) · [水体路线图](WATER_ROADMAP.zh-CN.md)。

W2 在 M14 长波图案上增加细波纹法线，并在单个像素无法分辨某组波纹时减弱它。
W2 已实现，CPU、离线编译和 W2 本机检查通过；历史水深颜色本机回归也已通过。
这里不声称画面、性能或 Minecraft／Iris 运行已经通过。

## 1. 范围与控制

| 设置 | 行为 |
|---|---|
| `WATER_SURFACE_DETAIL=1`（默认） | 三组长波加三组细波纹，分别按投影到像素的范围过滤 |
| `WATER_SURFACE_DETAIL=0` | 原 M14 三组长波路径，不使用新增过滤，供对照或回退 |
| `WATER_WAVES=0` 或波动强度为 0 | 原始、未扰动的反射法线 |
| 波动速度 0／1／2 | 与原来一样，静态空间图案／正常／双倍运动 |

新开关叫**水面细波纹**，位于“水面反射波动”之后。预设继续只控制原有七项，
新设置不是预设控制项，也不是滑块。轻量预设仍关闭水面反射波动，使细节不生效。

本阶段只改变反射法线。几何体、岸边轮廓、alpha、水深颜色及解析天空反射来源
保留原有职责。没有真实水流、流场、瀑布模型、折射、粗糙度模型或新反射算法。
W1 快照仍没有水面消费者；天空、相机浸水和表面朝向的原有限制仍存在。

## 2. 为什么分成长波与细波纹

原长波提供连贯、缓慢的大尺度变化；细波纹增加表面层次，不需要把高度参数也
放大到长波的级别。这些参数是人为设计的周期信号，不是实测水波频谱或流体模拟。
法线细节与网格位移面对不同采样限制。
[波浪模型参考](https://developer.nvidia.com/gpugems/gpugems/part-i-natural-effects/chapter-1-effective-water-simulation-physical-models)。

| 新增波纹 | 128 格周期内的整数方向 | 概念幅度（格） | 波长（格） | 每 200 秒时间谐波 |
|---|---|---:|---:|---:|
| 1 | `(49,19)` | 0.006 | 2.435556 | 24 |
| 2 | `(-83,31)` | 0.0035 | 1.444692 | -31 |
| 3 | `(151,97)` | 0.0015 | 0.713205 | 43 |

“概念高度”只用来推导坡度，不会移动顶点。原 `water_waves.glsl` 和
`water_wave_settings.glsl` 保持不变。细节关闭路径调用原辅助函数；新辅助函数
重现原三组长波并增加三组细波纹，原幅度、方向与时间谐波相同。
整数空间／时间谐波保持 128 格空间周期和正常速度下的 200 秒周期；有限精度下
的采样连续性结果记录在下方，不假定误差为零。传播方向来自相位符号，不是读取 Minecraft 的实际水流方向。

六组未过滤波纹的坡度上界约为 0.11857748。对水平水面、刚性视图变换和完整
适用权重，默认强度 0.6 的法线倾斜上界约为 4.06954 度；M14 原上界约 2.56498 度。
六组波纹在最大强度时的上界约为 6.76241 度。
这是数学上界，不是测得的典型运动或画质结论。这组参数作为第一版较为克制；
但掠射视角下，小幅法线变化也会明显移动反射，最终可见程度仍由实际合成决定。

## 3. 每组波纹分别按像素过滤

设 `p` 为连续的世界水平位置，单位是格；`q` 是某组波纹的整数周期方向。
空间频率为 `q/128`，单位是每格周期数。先估算 `dx=dFdx(p)`、`dy=dFdy(p)`，
再把像素覆盖范围投影到这组波纹方向：

```text
fx = dot(q/128, dx)       // 屏幕 x 方向每像素周期数
fy = dot(q/128, dy)       // 屏幕 y 方向每像素周期数
sinc(x) = sin(x)/x，且 sinc(0)=1
方形像素平均权重 = sinc(pi*fx) * sinc(pi*fy)
频率 = max(abs(fx), abs(fy))
奈奎斯特渐隐权重 = 1 - smoothstep(0.25, 0.5, 频率)
过滤后坡度 = 原坡度 * 方形像素平均权重 * 奈奎斯特渐隐权重
```

若相位在一个方形像素内是仿射变化，两个 sinc 的乘积就是该余弦分量的精确平均。
真实透视映射只在局部近似仿射。额外的 0.25→0.5 渐隐是主动选择的抗锯齿策略，
不是精确积分的一部分：只求像素平均，仍可能留下像素网格无法表达的高频。
每个屏幕轴在每像素 0.5 周期处达到半周期限制。
[采样理论](https://pbr-book.org/4ed/Sampling_and_Reconstruction/Sampling_Theory)。

着色器用 Horner 形式计算十次偶多项式，近似每个 sinc。截止条件先把参数限制在
`|x| < pi/2`；浮点舍入之前，交错级数余项小于 `3.63e-8`。
这是对上面精确像素平均公式的近似，不是宣称 GPU 运算完全精确。
开发时，Intel 上直接计算 `sin(x)/x` 在每像素 0.01 周期处出现约 `3.72e-6` 误差，
多项式避开了这个已观察到的近零三角函数问题。独立 CPU 参考仍计算精确
`sin(x)/x`，不会只重复着色器近似。最终本机过滤结果见下方。

权重同时考虑两个屏幕方向，不只看相机距离。斜视时，一个像素可能覆盖很长一条
水面，因此离相机近的区域也可能需要减弱细波纹。长波频率较低，会保留得更久。
这是一阶覆盖范围估计，在轮廓、断层和透视变化强烈的位置仍有局限。
[表面采样范围参考](https://www.pbr-book.org/4ed/Textures_and_Materials/Texture_Sampling_and_Antialiasing)。

## 4. 先求导，再折回周期与丢弃片元

水面片元路径先重建连续的视图位置，在 alpha 丢弃和各材质条件分支之前，
把它的 `dFdx`／`dFdy` 向量变换到世界 XZ，后续过滤再使用。仅在这个水面／细节
路径定义的标记，让后绘制雾复用已重建的位置。非有限或极端覆盖范围
（任一分量超过每像素 65,536 格）回到未扰动法线，不把错误输入当成零覆盖范围。
导数必须来自连续坐标：若先 `fract`，跨越 128 格边界会产生假的大覆盖范围，
可能在水面留下细节突然消失的条带。周期折回只用于相位求值。
原有小范围相机锚点继续帮助远坐标处的相位精度。

GLSL 导数假设表达式连续，在不一致的控制流中可能没有定义。提前计算避免了
这一特定问题，并不证明所有几何边缘或驱动路径都无瑕疵。
[Khronos 导数参考](https://raw.githubusercontent.com/KhronosGroup/OpenGL-Refpages/main/gl4/dFdx.xml)。

过滤坡度不等于完整的反射抗锯齿：法线归一化、菲涅耳、反射采样及后续锐利光照
都是非线性的。被过滤掉的小波纹方差还没有转为粗糙度，因此远水仍可能过于像镜面。
本阶段也没有时间过滤或运动模糊方案。
