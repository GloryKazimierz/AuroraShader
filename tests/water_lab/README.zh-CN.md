# Aurora 水体测试场——隔离的 Minecraft 场景

[English](README.md) · [场景坐标](scene.json)

这是面向 **Java 1.21.11／数据包 94.1** 的小型可重复水体场景，使用独立
`aurora_lab:water` 维度和必须手动调用的玩家函数。目前没有安装或运行于
Minecraft；画面、流体稳定、维度加载及 Iris 行为均**未观察**。
静态检查由仓库中的独立验证工具另行记录。

## 只安装到 D 盘的新建一次性测试世界

游戏目录和新存档都放在 D 盘。创建一次性世界时选入这个数据包；或者将本目录
（目录内直接有 `pack.mcmeta`）放到新存档的 `datapacks/aurora_water_lab/`，
再完整重新进入世界。使用 Minecraft 1.21.11，开启命令并保留正常命令限制。
仓库不会替你安装数据包、启动 Minecraft、修改世界、改变 junction，或将光影复制到 C 盘。

不要安装到历史或日常游玩的存档。自定义维度复用原版 overworld 类型，采用 ocean
群系，没有结构／装饰／湖泊，平坦石地表位于 y63；尚未建造时也有安全落脚点。

以玩家身份执行：

```mcfunction
/function aurora_lab:enter
/function aurora_lab:build
/function aurora_lab:status
```

建造前在起点等待区块加载。函数要求玩家在测试维度中、距离 (0,64,0) 不超过
8 格，并在任何写入前检查涉及的全部 36 个区块。没有完成消息时先查看 status：
若尚未开始，可在中心等待或提高测试世界视距／模拟距离后重试。
没有强制常加载区块、定时命令或 load／tick 自动函数。

所有方块写入只发生在专用维度的 x/z -40..39、y47..82。最大 fill 为 30,400 格，
低于通常的 32,768 限制。写入前保存 `aurora_lab:state` 的 started 锁；
25 处关键静态方块检查全部通过后才设置 ready。
started 存在但 ready 不存在代表**部分建造**，不是成功。没有自动回滚／重置／
重建：请用新的测试存档恢复，不要清锁去覆盖后来自己建的东西。
引擎中断或自定义命令限制不能保证事务性；完成后的建造不会再次覆盖后续建筑。

## 几何与水深标定

静水池最高的源水方块均为 y63。平坦内部、上方为空气时，原版源水表面通常接近
**63+8/9**，不是 y64；实际版本／资源包仍需观察。源水方块层数是方块网格标定，
不是光学光程。

| 水池／采样 x,z | 底板方块 y（顶面） | 源水 y／层数 | 预计竖直自由表面间距 |
|---|---|---|---|
| 浅池／-21,-21 | 61（62） | 62..63／2 | 约 1.8889 格 |
| 深池／21,-21 | 47（48） | 48..63／16 | 约 15.8889 格 |
| 有顶洞穴／-20,24 | 59（60） | 60..63／4 | 约 3.8889 格 |
| 玻璃／冰带／8,18 | 61（62） | 62..63／2 | 约 1.8889 格 |
| 瀑布接水池／26,30 | 59（60） | 60..63／4 | 约 3.8889 格 |

彩色墙、柱和细铁栏用于倒影与轮廓判断。洞穴池屋顶位于 y70，有干燥平台与两支火把。
东南测试带放置玻璃板状墙和普通冰，作为**非水材质对照**。

高处水槽源水位于 y72、底板 y71，出口朝 **+Z**。预期原版水流经过六格露出的
槽底，在 z19 下落到接水池；记录前等待正常流体更新。哨点只检查水源／槽体，
不把尚未观察的流动稳定状态标成成功。这些是原版流体输入，不表示 Aurora 已实现自定义水流。

## 九个固定镜头

采用第一人称，固定 FOV（建议 70）、16:9 分辨率和一致的光影／资源包设置。
以下坐标是**脚底**，yaw／pitch 单位为度。假定站立／旁观眼高为 1.62 格；
潜行、游泳、第三人称、相机模组及未来几何波浪会改变结果。

函数不改游戏模式。标注“旁观”的镜头需自行选择旁观模式，例如在该测试世界中
执行 `/gamemode spectator`。站立镜头保持直立并落地，两次对比姿态相同。

每个名称前加 `/function aurora_lab:view/`。

| 名称 | 脚底 x,y,z | yaw／pitch | 姿态与目的 | 观察结果 |
|---|---|---|---|---|
| shallow_overhead | -21.5,82,-21.5 | 180／90 | 旁观，垂直水深／法线基线 | |
| deep_grazing | 21.5,64,-3.5 | 180／6 | 站立，掠视倒影与水深 | |
| cave | -20.5,64,11.5 | 0／10 | 平台站立，火把局部光／无室外天空 | |
| glass_ice | 1.5,64,18.5 | -90／12 | 站立，玻璃／冰分类与叠层 | |
| waterfall | 32.5,70,29.5 | 135／18 | 旁观，+Z 水槽、下落侧面及落点 | |
| underwater | 21.5,54,-21.5 | 180／-45 | 旁观，中心视线在深池内到达水面 | |
| waterline_above | 21.5,62.468888889,-21.5 | 180／0 | 旁观，名义眼点高于表面 0.20 格 | |
| waterline_center | 21.5,62.268888889,-21.5 | 180／0 | 旁观，名义眼点在表面，然后缓慢上下移动 | |
| waterline_below | 21.5,62.068888889,-21.5 | 180／0 | 旁观，名义眼点低于表面 0.20 格 | |

above／below 是介质对照；水平视角下，它们距离约 0.05 格的近平面范围太远，
不能保证出现画面一半水上一半水下。该实验使用 **center 加旁观模式的缓慢竖直扫动**，
并记录实际 FOV、眼高／脚底高度、姿态、俯仰角及流体判定。
Minecraft 的眼点流体测试可能与可见界面不同；场景本身不能证明逐像素介质处理
或分割水线已经成功。

## 可选时间／天气轨迹——只用于一次性世界

这些都是手动命令，数据包不会自动执行。时间／天气／游戏规则可能影响该存档的
其他维度，因此只在一次性测试存档使用，并记录对比时的状态。

```mcfunction
/gamerule minecraft:advance_time false
/gamerule minecraft:advance_weather false
/time set 6000
/weather clear
```

| 条件 | 手动改变 |
|---|---|
| 正午基线 | `/time set 6000` 与 `/weather clear` |
| 夕阳 | `/time set 12000` |
| 夜晚 | `/time set 18000` |
| 雨天 | `/time set 6000` 与 `/weather rain`，等待天气过渡稳定 |

记录光影提交、Iris／Fabric／游戏版本、GPU／驱动、分辨率、FOV、资源包、镜头、
时间／天气及设置。先对比正常画面与 DEBUG_VIEW 7／8／9，再保持场景不变对比
SSR 开关及 64／128 步。每组留一张静态图和一段短运动序列。
空白结果仍代表未观察，静态工具不会虚构截图或 FPS。

## 没有启动 Minecraft 时能检查什么

[静态验证器](../../tools/validate_water_lab.py)已通过：36 个区块加载保护、50 项有界
方块操作、25 个完成哨点、五条水柱标定和全部九个镜头。九个内存反例拒绝了缺失保护、
错误维度／越界以及被禁止的自动或世界状态命令。
可在仓库根目录运行 `python -B tools/validate_water_lab.py`。

仓库中的独立验证器检查精确包版本／维度格式、绝对方块边界、一次性／区块加载保护、
fill 体积、关键几何、镜头所在区域及眼点／中心视线关系。
它不执行 Mojang 命令解析器，不模拟流体／光照，不加载维度、不验证光影集成，
也不测性能。ready 只表示静态哨点通过。

格式已与本机官方 1.21.11 客户端中的 version.json、flat 世界预设和内置数据包
元数据核对，未将游戏资源复制到此目录。
